# Ideas

## AI-assisted encoding (шаги 2 и 3)

### Контекст
В slow encode / skipped / encoding режимах пользователь проходит 4 шага запоминания слова.
Шаги 2 и 3 требуют творческих усилий и иногда вызывают ступор.

### Идея
Добавить кнопку "Подсказать" на шагах 2 и 3 — AI генерирует вариант как толчок, не как замену.

**Шаг 2 — звуковая ассоциация:**
Берём английское слово + транскрипцию → находим русское слово с похожим звучанием.
Пример: `"purple"` → звучит как "пёрпл" → предлагает "перепел", "пёрышко".

**Шаг 3 — сцена:**
Берём sourceText (русское слово) + soundAssociation (ассоциация из шага 2) → генерируем сцену где два образа взаимодействуют.
Пример: `"purple"` + "перепел" → *"Перепел сидит на троне в фиолетовой мантии"*.

### Важно
Своя ассоциация запоминается лучше. AI — только как разблокировка если совсем застрял, не как замена.

### Стек
- **Groq API** (бесплатный tier) — быстро, достаточно для этой задачи
- Модель: Llama 3 или Mixtral
- Реализация: Next.js Server Action → Groq API → варианты пользователю
- Fine-tuning не нужен, достаточно few-shot prompt с примерами

## Паузы в больших списках/паттернах (100+ элементов)

### Контекст
Списки слов и паттерны могут быть большие (100 слов/предложений). После ~20 карточек подряд
в режимах вроде Selection/Encoding/Recall (слова) или First Pass/Full Practice (паттерны)
падает внимание — это не проблема памяти, а проблема концентрации за один присест.
Review-режим на FSRS этой проблемы не имеет: он сам размазывает нагрузку по дням через `enable_fuzz`.

Рассматривались два варианта решения, ни один пока не реализован.

### Вариант 1 — пауза по счётчику сессии (проще)
Добавить чек-поинт каждые N карточек (например, 20) прямо в существующих компонентах режимов
(`SelectionMode`/`EncodingMode`/`RecallMode` у слов, `SentencePracticeFlow` у паттернов).
Как только `doneCount` кратен порогу и очередь не пуста — вместо автоперехода к следующей карточке
показываем экран "Сделано N, осталось M — Продолжить / Хватит на сегодня".

Плюсы:
- Не трогает БД/схему — очередь как загружалась целиком на клиент, так и загружается.
- Работает сразу для уже существующих больших списков, ничего пересоздавать не надо.
- Одинаково применимо и к таймed-режимам, и к обычным.

### Вариант 2 — жёсткий лимит 20 на список/паттерн + авто-разбивка при импорте
- Список/паттерн не может содержать больше 20 элементов: `addWordsToListAction`/`importSentencesAction`
  отклоняют добавление сверх лимита, предлагая создать новый список.
- При импорте >20 элементов сразу создаём N списков/паттернов с именами вида
  "Название 1", "Название 2", ...
- Урок ссылается на несколько списков/паттернов вместо одного — уже поддерживается структурно
  (`lesson_word_lists`/`lesson_patterns` — таблицы many-to-many).
- Общий прогресс по теме (по списку) не нужен — важен только агрегированный прогресс по уроку.
  Такого агрегата сейчас нет: `LessonDetails.tsx` просто показывает названия привязанных
  списков/паттернов со ссылками, без сводки по прогрессу — это отдельная новая фича.
- Чинит только новые импорты; существующие большие списки придётся разбивать вручную.

### Вывод
Вариант 1 — меньше усилий, ничего не ломает, работает ретроактивно на старых списках.
Вариант 2 — переиспользует существующую механику списков вместо новой сущности "блок",
но требует новой валидации, авто-разбивки при импорте и новой фичи агрегированного
прогресса на уровне урока. Решение пока отложено, оба варианта записаны для дальнейшего обсуждения.
